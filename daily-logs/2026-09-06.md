## 오늘 한 일 — 스튜디오 Fee 얼리버드 옵션

관리자 페이지에서 코스별로 **얼리버드 스튜디오 Fee + 마감일**을 설정하면,
정가 시작일 전날까지는 얼리버드 가격이, **그날 00:00(LA 기준)부터는 자동으로 정가**가
사이트·웰컴 이메일 양쪽에 반영되도록 구현했다. 별도 조작이 필요 없다.

### 규칙 (한 곳에서만 판정)
- `early_until`은 **정가가 시작되는 날**이다. 금액(`fee_early`)과 날짜가 **둘 다** 있고
  `오늘(America/Los_Angeles) < 정가 시작일` → 얼리버드 가격, 아니면 정가(`fee`).
- 예) `2026-10-01` → **9/30까지 얼리버드, 10/1부터 정가.**
  (사용자 확인: "10/1까지"라고 쓰면 9/30이 마지막 날이고 10/1부터 정가라는 뜻)
- 사이트·이메일 표기는 **마지막 날**로 — `Early bird — through Sep 30` / `얼리버드 — 9월 30일까지`.
- 시간대는 **무조건 LA(PST/PDT) 기준**. 보는 사람 기기 시간대는 판정에 쓰지 않는다 —
  한국 기기가 이미 9/7이어도 LA가 9/6이면 9/6으로 판정된다. Intl을 못 쓰는 예비 경로도 UTC가 아닌 PST(UTC-8)로 계산.

## 추가 — 설정값을 스크립트 속성으로 분리 (보안)

사용자가 실제 운영 설정값(SENDER_ALIAS/REPLY_TO/ADMIN_KEY)을 저장소 파일에도 반영해 달라고 요청.
**저장소가 public**이라 비밀번호·개인 이메일을 코드에 커밋하면 그대로 노출된다 —
관리자 페이지에는 신청자 이름·이메일·전화번호가 보이므로 비밀번호 노출은 곧 개인정보 노출.
→ 사용자 승인 받아 **스크립트 속성(Script Properties)** 방식으로 전환.

### 코드 변경 (`apps-script/google-apps-script.js`)
- `config_(name, fallback)` 신설 — 스크립트 속성을 먼저 읽고, 없으면 파일 상단 상수(예비값) 사용.
  속성 접근 실패(예외)도 삼키고 예비값으로 넘어간다.
- 접근자 4개: `adminKey_()`, `notifyEmail_()`, `senderAlias_()`, `replyTo_()`.
  기존 상수 직접 참조는 전부 이 함수 호출로 교체 (auth / registrations / all=1 / updateCourses / 알림메일 BCC / 웰컴메일 from·replyTo).
- 파일 상단 상수 4개는 **전부 빈 문자열**로 유지 — 공개 저장소에 값이 올라가지 않는다.
- `?all=1`(숨김 코스 포함 조회)을 fail-closed로 통일 — 비밀번호 미설정 시에도 거부한다(이전엔 통과).
- 로그인 실패 안내 문구를 "스크립트 속성에 ADMIN_KEY를 추가하세요"로 변경.

### 값을 바꾼 이점
- 파일 전체를 다시 붙여넣어도 비밀번호·이메일이 지워지지 않는다.
- 값 변경 시 **재배포 불필요** (실행 시점에 읽으므로).

### 검증

## 추가 — 날짜 셀을 시트 시간대로 읽도록 수정

사용자 질문("upgradeCoursesTab을 꼭 실행해야 하나?")을 계기로 확인한 실제 버그.

- `early_until`(P열)이 텍스트 서식이 아니면 구글 시트가 `2026-10-01` 입력을 **날짜 객체**로 저장한다.
  이 값은 "**스프레드시트 시간대**의 자정"인데, `dateToString_`이 이를 LA 시간대로 포맷하고 있었다.
  → 시트 시간대가 서울이면 서울 자정 = LA 전날 08:00 → **`2026-09-30`으로 하루 밀려 읽힘.**
- 수정: 날짜 셀은 `sheetTimezone_()`(스프레드시트 시간대 → 스크립트 시간대 → LA 순 폴백)으로 포맷.
  얼리버드 **판정**은 그대로 LA 기준(`studioToday_`) — 바뀐 건 셀 값을 문자열로 되돌리는 부분뿐.
- 검증: 시트 시간대 Seoul / LA / UTC / New_York 네 경우 모두 `2026-10-01`로 정확히 읽힘. 텍스트 셀·빈 셀도 정상.

이 수정으로 `upgradeCoursesTab`을 실행하지 않아도(=P열 텍스트 서식이 없어도) 날짜가 밀리지 않는다.
다만 열 이름표(헤더)와 서식 고정을 위해 한 번 실행하는 것은 여전히 권장.
