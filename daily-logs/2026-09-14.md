## 오늘 한 일 — 관리자 페이지: 코스 ID 자동 지정 + 신청 수 집계 버그

사용자 요청 두 가지.
1. 관리자 페이지에서 코스마다 A, B, C를 손으로 적던 것을 **일정 순서로 자동 지정**되게.
2. `Level 1 Apprentice Review Course`에 등록자가 1명 있는데 정원이 그대로 `8`로 나오는 문제 확인.

### 2번 원인 (코드 분석 — 이 환경에서는 script.google.com 접속이 막혀 실제 시트는 못 봄)
- 신청 수는 접수 시트 B열의 `"D - 코스명"` 문자열에서 **글자(id)만** 뽑아 세고 있었다 (`countRegistrations_`).
- 그래서 (a) 관리자가 ID 글자를 손으로 바꿨거나(예: D→C), (b) 사이트가 시트를 못 읽어 코드에 내장된 예비 목록
  (`TrainingForm.tsx`의 `COURSE_VALUES`, Review 코스 = `D` 고정)으로 접수된 경우, 그 신청은 현재 코스에 안 맞아 0으로 집계된다.
  Review 코스가 정확히 이 케이스 — 예비 목록의 글자가 시트의 글자와 달랐을 가능성이 크다.
- ID를 자동으로 다시 매기는 1번 기능을 넣으면 이 문제가 더 자주 생기므로 **둘을 같이 고쳐야 했다.**
- 참고: 이메일(D열)에 `@`가 없는 행은 등록자 탭에도, 집계에도 안 잡힌다. 시트에 직접 적은 등록자라면 이메일 칸을 채워야 한다.

### 변경 파일
- `apps-script/google-apps-script.js`
  - `normalizeKey_`: 코스명 비교용 정규화 (대소문자·®™·대시 종류·따옴표·공백 무시).
  - `resolveCourseIndex_`: 접수 항목 하나를 현재 코스 목록에 매칭 — **코스명(영/한) 우선, 안 맞을 때만 글자(id)**.
  - `countRegistrations_(ss, courses)`: 코스 배열과 같은 순서의 신청 수 배열 반환. 한 신청 행에서 같은 코스 중복은 1명.
    어디에도 안 맞는 신청(삭제된 코스)은 세지 않는다. 숨김 코스도 매칭 대상에 포함해 글자가 겹쳐도 보이는 코스로 새지 않게.
  - `doGet`: Courses 탭 전체(숨김 포함)를 먼저 읽고 → 집계 → active 필터 순으로 재구성. 응답 JSON 형식은 동일.
- `public/admin/index.html`
  - ID 칸은 `readonly` (같은 스타일, 배경만 sand). 직접 입력 불가.
  - `firstDateOf`: 일정 텍스트에서 첫 날짜 추출. 지원 형식 `7/24`, `7/24/26`, `7/24/2026`, `2026-07-24`, `Jul 24`, `July 24, 2026`, `7월 24일`.
    연도 없는 날짜는 **오늘(LA)과 가장 가까운 해**로 해석 (9월에 `1/10` → 다음 해, `7/24` → 올해).
  - `autoOrder`: **표시 중인 코스 → 일정 순**, 그 뒤 **숨긴 코스 → 일정 순**, 일정 없음/못 읽음은 각 그룹 맨 뒤(기존 순서 유지). 그 순서로 A, B, C… (Z 다음 AA).
    숨긴 코스를 뒤로 보내는 이유: 사이트에는 표시 코스만 나오므로 방문자에게 항상 A, B, C가 빈칸 없이 이어진다.
  - `applyOrder`: 일정 칸 수정(blur) 또는 표시 체크 변경 시 즉시 재정렬·재부여하고 옮겨간 카드로 스크롤. 얼리버드 체크 상태·입력값·신청 수(`data-taken`)는 다시 그려도 유지.
  - 불러올 때도 정렬해서 보여주고, 시트 순서와 다르면 하단에 "일정 순서에 맞춰 ID를 다시 매겼습니다 — 저장을 누르면 사이트에 반영됩니다" 표시.
  - 저장 시: 빈 카드(이름·일정 전부 없음) 제외 → 정렬·부여 → 전송. 시트 행 순서 = 사이트 순서.
  - `+ 코스 추가`: 다음 글자로 카드 생성, 포커스는 코스명(영문)으로.
  - 등록자 탭: 칩과 필터의 글자를 **현재 코스명 기준으로 환산** (`resolveCourseId`, Apps Script와 같은 규칙). 필터에 코스명 표시 (`B · GYROTONIC® … (2명)`).
  - 안내문(hint)에 자동 지정 규칙과 코스명 집계 한 줄씩 추가.
- `apps-script/SETUP-KO.md`: id 자동 지정, 집계 방식(코스명 우선, 이메일 필수), 새 코스 추가 방법 갱신.

## 추가 — 재배포 후에도 정원이 안 바뀐다는 보고 → 진단 장치 추가

사용자가 Apps Script를 재배포했는데도 Review 코스 신청 수가 그대로라고 함. 이 환경에서는 시트를 볼 수 없어
**관리자 페이지에서 원인이 보이게** 만들었다.

- `apps-script/google-apps-script.js`
  - `SCRIPT_VERSION = '2026-09-14b'` — `doGet` 응답(코스 목록·등록자 목록)에 `version` 포함.
  - `resolveCourseIndex_`: 정확 일치 다음에 **부분 일치** 추가 — 한쪽 이름이 다른 쪽을 포함하는 코스가 **딱 하나**일 때만 인정
    (`Level 1 Apprentice Review Course` ↔ `GYROTONIC® Level 1 Apprentice Review Course`). 둘 이상이면 모호 → 글자(id)로.
  - `splitCourses_`: 쉼표 뒤 공백 없음·줄바꿈 구분(수기 입력)도 항목으로 인식.
- `public/admin/index.html`
  - 안내문 하단에 **Apps Script 버전** 표시: `최신` / 버전 다름 → "재배포가 반영되지 않았습니다" / 없음 → "구버전, 재배포 필요".
    → "새 배포"로 주소가 바뀐 경우나 저장 전 배포를 바로 잡아낼 수 있다.
  - 등록자 카드: 현재 코스 어디에도 안 맞는 접수 항목이 있으면 **"⚠️ 현재 코스와 매칭 안 됨 — 집계 제외: …" 칩**(clay) 표시.
    매칭 규칙은 스크립트와 동일(정확 → 부분(유일) → 글자).
- 검증: 매칭 8케이스(글자 다름·접두어 없음·모호한 "Foundation Course"·한글명·삭제된 코스), 분리 4형식, 헤드리스 렌더로 버전 칩 3상태와 경고 칩 확인. 빌드·린트 통과.
