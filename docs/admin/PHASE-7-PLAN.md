## 1. 출발점

| 필요한 것 | 지금 상태 | 이번 처리 |

| 결제 (`payment_transactions`) | Phase 5. PAYMENT / REFUND, VALID / VOID, 받은 직원 | 읽기만 |

## 2. 이번 단계에서 하는 것

### DB (마이그레이션 1개 `…_finance_closing.sql`, 기존 테이블은 컬럼 추가만)
- `finance_report(from, to)` (오너만): J.1 수치 전부를 jsonb 하나로 — 총매출, 환불, 순매출, 결제 건수, 운영 지출(지급·미지급),
  추정 영업이익, 결제수단별·받은 직원별·카테고리별, 월별(마감 상태 포함), 무효·추정·미지급 건수.
  대시보드·리포트·마감·CSV가 모두 이 함수 하나의 숫자를 쓴다 (J.2-7).
- `close_period(month)` (오너만): 끝난 달만 마감. 마감 순간의 `finance_report`를 스냅샷으로 저장, 버전 +1, 감사 기록.
  마감하는 동안 들어오는 결제·지출 입력은 기다렸다가 거부된다 (테이블 잠금으로 직렬화).
- `reopen_period(month, reason)` (오너만): 사유 필수, 감사 기록. 다시 마감하면 버전 2.
- 지출 잠금 트리거 수정: 마감된 달이어도 지급 상태(지급일·지급 방법)만 바꾸는 것은 허용 (금액·날짜는 그대로 잠김).

### 화면
- **대시보드 (오너)**: 오늘 매출 옆에 "이번 달" 카드 — 순매출, 운영 지출(미지급 표시), 추정 영업이익.
  최근 12개월 매출 대 지출 막대 차트. 대시보드를 열 때 정기 지출을 먼저 생성한다 (J.3).
- **Reports `/admin/reports/` (오너, 사이드바 Admin 그룹)**:
  - Overview 탭: 월 / 연도 선택, 손익 요약(총매출 − 환불 = 순매출 − 운영 지출 = 추정 영업이익), 계산 기준 안내,
    결제수단별·받은 직원별·카테고리별, 월별 표(마감 상태), CSV 내보내기.
  - Monthly closing 탭: 달 선택(기본 = 지난달), 확인 4단계(결제 / 환불·무효 / 지출(추정·미지급 경고) / 결과),
    4개 모두 확인해야 마감 버튼 활성, 확인 대화상자. 마감 후 "누가·언제·버전", 재오픈(사유 필수), CSV.

## 3. 하지 않는 것

- **조정(Adjustment) 거래**: 마감된 달의 오류는 재오픈 → 정정 → 다시 마감으로 처리한다. 결제 테이블 구조를 바꾸지 않는다.
  필요해지면 나중에 추가.
- 리포트 필터(결제수단·강사·카테고리 선택), 사용자 지정 기간, 일별 차트, 인쇄 전용 화면 (브라우저 인쇄로 충분).
- pg_cron, Mindbody·Schedulista 연동 (보류).
- 공개 홈페이지 변경 없음.

## 4. 결정한 기본값 (바꾸고 싶으면 말씀 주세요)

1. 이번 달(아직 안 끝난 달)은 마감할 수 없다. 마감하면 직원 결제 입력이 막히기 때문.
2. 모든 지출 카테고리를 운영 지출로 계산한다 (12개 모두 운영비).
3. 미지급 지출도 그달 지출에 포함한다 (J.1). 미지급이 있어도 마감 가능, 마감 후에도 지급 처리 가능.
4. 매출은 받은 날 기준, 환불은 돌려준 날 기준 (J.2). 화면에 "은행 잔고·세금상 이익이 아닌 경영 참고용 추정치" 안내.
