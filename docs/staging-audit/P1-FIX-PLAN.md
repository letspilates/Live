## 1. AUDIT-003 강사 삭제 시 일정에서 강사가 지워짐

**원인:** `appointments.staff_id`, `created_by`가 "삭제되면 비우기(SET NULL)"로 되어 있다. 그래서 "기록이 있는 사람은 삭제 대신 비활성화" 안전장치가 일정에는 작동하지 않는다.

**고칠 내용**
- 새 마이그레이션: 두 연결을 "기록이 있으면 삭제 거부(RESTRICT)"로 바꾼다.
- 결과: 일정이 있는 사람은 Users › Delete를 누르면 기존 문구 "이 사람은 기록이 있습니다. 대신 비활성화하세요."가 나온다. 로그인 계정도 지워지지 않는다(staff-admin이 DB 확인 후에만 로그인을 지움, 확인함).
- 기존 데이터는 바뀌지 않는다.

**파일:** `supabase/migrations/20261013010000_p1_fixes.sql`(새 파일, 2번과 공유), `supabase/tests/users.test.sql`

**테스트:** 일정이 있는 강사 삭제 → 거부되고 일정의 강사가 그대로인지 (로컬 DB).

## 2. AUDIT-004 새로고침 안 한 캘린더가 다른 사람의 예약을 취소함

**원인:** 일정을 저장할 때 화면이 "내가 마지막으로 불러온 클라이언트 목록"을 통째로 보내고, 서버는 목록에 없는 예약을 취소로 처리한다. 다른 사람이 그사이 넣은 예약은 목록에 없으니 취소된다.

**고칠 내용**
- **길이 조절(아래 모서리 드래그):** 시간 길이만 바꾸고 예약은 건드리지 않게 한다(`keep_clients`).
- **일정 창에서 저장:** 화면이 불러온 시점의 "마지막 수정 시각"을 같이 보낸다. 그사이 누가 바꿨으면 저장을 거부하고 이 문구를 보여준 뒤 캘린더를 새로 불러온다.
  - EN: "Someone else changed this appointment. It has been reloaded; please make your change again."
  - KO: "다른 사람이 이 일정을 먼저 수정했어요. 새로 불러왔으니 다시 수정해 주세요."
- 드래그로 옮기기(`move_appointment`)는 원래 예약을 건드리지 않아 그대로 둔다.
- 화면 배치·색·버튼은 바뀌지 않는다. 새 오류 문구만 추가된다.

**파일:** 같은 마이그레이션(`save_appointment` 교체), `src/admin/schedule.ts`(불러올 때 수정 시각 포함), `src/admin/pages/Schedule.tsx`(길이 저장·창 저장), `src/admin/i18n.ts`(문구), `supabase/tests/schedule.test.sql`, `tests/admin-shell.mjs`

**테스트**
- 로컬 DB: A가 연 상태에서 B가 클라이언트 추가 → A가 길이 변경 → B의 예약이 그대로 BOOKED.
- 로컬 DB: A가 오래된 창에서 저장 → 거부.
- 화면 테스트: 거부 시 문구가 보이고 캘린더가 다시 불러와지는지.

## 3. AUDIT-005 자정 넘어 열어둔 결제 화면이 전날로 기록함

**원인:** Owner/Admin의 결제 날짜 칸이 화면을 연 시점의 날짜로 고정된다. 자정을 넘기면 그 날짜가 "직접 고른 과거 날짜"로 전송된다.

**고칠 내용**
- 날짜를 **직접 바꾼 경우에만** 과거 날짜를 보낸다. 안 건드렸으면 저장하는 순간의 오늘(LA)로 기록한다.
- 날짜 칸도 자정이 지나면 오늘로 바뀐다(오른쪽 결제 목록이 이미 쓰는 1분 확인을 같이 사용).
- 대시보드의 "오늘" 숫자도 자정이 지나면 새로 불러온다.
- Staff/Instructor는 원래 서버가 날짜를 정해서 영향 없음.

**파일:** `src/admin/pages/DailyIncome.tsx`, `src/admin/pages/Dashboard.tsx`, `tests/admin-shell.mjs`

**테스트:** 가짜 시계로 LA 23:50에 화면을 열고 00:05에 저장 → 오늘 날짜로 저장되는지, 날짜 칸과 대시보드가 바뀌는지.
